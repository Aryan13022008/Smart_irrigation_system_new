# Data Dictionary

Column-by-column description of every table in this dataset. Statistics are computed over all
five sectors pooled. All files are UTF-8 CSV, comma-separated, with a header row, `.` as decimal
separator and empty strings for missing values. All timestamps are local time (Europe/Rome),
naive, format `YYYY-MM-DD HH:MM:SS`.

---

## 1. Raw layer — `01_raw_data.zip`

### 1.1 `raw_sensor/MEASUREMENT_*.csv`

Direct export of the platform's measurement table. `MEASUREMENT_all.csv` contains all sensor
nodes; the other seven files are exact subsets of it split by sensor type. 486,894 rows in the
complete export, covering 2025-02-10 12:31 to 2025-09-26 16:31.

| Column | Type | Unit | Description |
|---|---|---|---|
| `#` | integer | — | Export row counter. No analytical meaning. |
| `pk_measurement` | integer | — | Database primary key of the measurement. Unique; usable to join the split files back to `MEASUREMENT_all.csv`. |
| `value` | float | sensor-dependent | Calibrated reading. °C for `STE`/`STI`, % RH for `SUE`/`SUI`, µS/cm for `*_CE`, pH units for `*_PH`. Empty or 0 for `SUT` soil-moisture nodes, which report in `humidity_percentage` instead. |
| `uncalibrated_value` | float | sensor-dependent | Raw reading before calibration. Missing in 11.4 % of rows. |
| `humidity_percentage` | float | % | Soil moisture, relative probe output on a 0–100 scale. Populated only for `SUT` nodes (11.4 % of rows); empty for all others. |
| `unit_of_measure` | string | — | **Empty for every row** in this export. Retained for fidelity to the source. |
| `measurement_date` | timestamp | — | Acquisition time. |
| `fk_iot_node` | string | — | Sensor node identifier. See §5 for the naming scheme. |

Rows per file: `all` 486,894 · `ph` 147,135 · `sti` 82,951 · `sui` 82,950 · `ce` 70,432 ·
`sut` 55,272 · `sue` 19,145 · `ste` 19,138.

### 2.4 `preprocessed/dataset_zone_{1..5}_preprocessed.csv`

Cleaned, feature-engineered, analysis-ready tables. Row counts and coverage per sector
are listed in README §4. The only missing values are the last 144 rows of `real_moisture_delta`
in each file.

> **Read README §7 before using these tables.** Three of its items change what the columns below
> mean: the 24-hour windows are counted in rows rather than hours, water volumes assume 1.1 L/min
> in every sector, and a few pH and EC values are sensor error codes.

| Column | Type | Unit | Range (pooled) | Role | Description |
|---|---|---|---|---|---|

| `weather_rain` | float | mm | 0 – 19.53 | feature | As in the merged layer. |
| `weather_pressure` | float | hPa | 996.11 – 1029.49 | feature | As in the merged layer. |
| `weather_wind_speed` | float | km/h | 0.02 – 41.82 | feature | As in the merged layer. |
| `weather_radiation` | float | W/m² | 0 – 813.32 | feature | As in the merged layer. |
| `soil_temperature_0-7cm` | float | °C | 4.33 – 44.18 | feature | As in the merged layer. |
| `soil_temperature_7-18cm` | float | °C | 7.80 – 33.30 | feature | As in the merged layer. |
| `ec` | float | µS/cm | −32256 – 31488 | feature | Time-interpolated (limit 2 steps). **Not range-filtered** — see README §7. |
| `ph` | float | pH | 0 – 76.75 | feature | Time-interpolated (limit 2 steps). **Not range-filtered** — see README §7. |
| `soil_moisture` | float | % | 0 – 100 | feature | Cleaned: range-filtered to 0–115, clipped at 100, despiked (9-sample window, 15-point threshold), trailing flatlines trimmed, then time-interpolated. |
| `irrigation_duration_minutes` | float | min | 0 – 10 | feature | Minutes of valve opening in the bin. |
| `month` | integer | — | 2 – 9 | feature | Calendar month. |
| `day` | integer | — | 1 – 31 | feature | Day of month. |
| `hour` | integer | — | 0 – 23 | feature | Hour of day. |
| `day_period` | integer | — | 0 – 3 | feature | 0 = 05:00–12:00, 1 = 12:00–17:00, 2 = 17:00–21:00, 3 = 21:00–05:00. |
| `quarter` | integer | — | 1 – 3 | feature | Calendar quarter. |

| `target_mean_24h` | float | % | 0 – 95.81 | **target** | Mean soil moisture over the following 144 rows. Same horizon caveat as `target_point_24h`. |
| `water_vol_to_24h` | float | L | 0 – 832.70 | feature | Water applied over the following 144 rows, at 1.1 L/min in every sector — see README §7. Forward-looking, so it is a valid input only where the irrigation schedule is known in advance; using it in a purely predictive setting is leakage. |
| `water_vol_past_4h` | float | L | 0 – 262.90 | feature | Water applied over the preceding 24 rows, at 1.1 L/min — same two caveats as `water_vol_to_24h`. Backward-looking, so safe to use as a feature. |
| `real_moisture_delta` | float | % | −79 – 75.92 | diagnostic | Soil moisture 144 rows ahead minus current soil moisture. Used only for the physical-consistency check (Spearman correlation against `water_vol_to_24h`). **Never use as a feature.** Null in the last 144 rows of each file. |

Calendar features (`month`, `day`, `hour`, `day_period`, `quarter`) are present in every file but
are worth using with care: they let a flexible model memorise the season instead of learning the
water–moisture response. They are kept in the published tables so that the choice is left open.

## 3. Suggested minimal load

```python
import pandas as pd

df = pd.read_csv("preprocessed/dataset_zone_1_preprocessed.csv", parse_dates=["ts"])

# recommended cleaning of the surviving pH / EC sensor error codes
df = df[df["ec"].between(0, 1000) & df["ph"].between(3, 9)]

# sector 5 only: water volumes were computed at 1.1 L/min instead of 0.4 L/min
# df[["water_vol_to_24h", "water_vol_past_4h"]] *= 0.4 / 1.1

FEATURES = [
    "weather_temp", "weather_humidity", "weather_rain", "weather_pressure",
    "weather_wind_speed", "weather_radiation",
    "soil_temperature_0-7cm", "soil_temperature_7-18cm",
    "ec", "ph", "soil_moisture", "irrigation_duration_minutes",
    "water_vol_past_4h",
    "water_vol_to_24h",   # DROP THIS for a purely predictive benchmark
]
TARGET = "target_mean_24h"
```

If the true 24-hour horizon matters for your work, rebuild the targets from the merged layer
rather than correcting the published files afterwards: the realised horizon of a row cannot be
recovered from the preprocessed files alone.

## 4. Agronomic classes

Soil moisture is mapped to five classes using the sector's soil parameters (README §3).
The class is not stored in the published files; it is derived at analysis time by
`config.agronomic_class()`.

| Class | Label | Condition | Colour used in the figures |
|---|---|---|---|
| 0 | Danger | moisture < PWP | `#b53b22` |
| 1 | Stress | PWP ≤ moisture < MADP | `#c6be73` |
| 2 | Optimal | MADP ≤ moisture < FC | `#91c05b` |
| 3 | Excess | FC ≤ moisture < SP | `#79a2a1` |
| 4 | Saturation | moisture ≥ SP | `#39b3e0` |

## 5. Node identifier scheme

| Pattern | Meaning |
|---|---|
| `SUT0000n` | Soil moisture probe, sector *n* |
| `SNPK0000n_CE` | Soil electrical conductivity probe, sector *n* |
| `SNPK0000n_PH` | Soil pH probe, sector *n* |
| `STE00001` | Air temperature, outdoor |
| `STI00001` | Air temperature, indoor |
| `SUE00001` | Air relative humidity, outdoor |
| `SUI00001` | Air relative humidity, indoor |
| `SV00001` | Auxiliary probe present only in `MEASUREMENT_all.csv`; unused |
| `AIRR0000n` | Irrigation valve, sector *n* |
| `AFIRR00001` | Fertigation unit, channels 1–4 |

Sector membership is extracted from the trailing digit of the node ID (`SUT00003` → sector 3),
and for `SNPK` nodes from the digit preceding the `_CE` / `_PH` suffix. Node IDs ending in `6`
exist in the raw telemetry but are not part of the five analysed sectors.
